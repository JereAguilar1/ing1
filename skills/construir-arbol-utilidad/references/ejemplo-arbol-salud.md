# Ejemplo de referencia: árbol de utilidad para un sistema de salud (formato tabular)

Este ejemplo es solo para validar el FORMATO de la tabla — no lo copies para otro dominio.

| Atributo | Refinamiento | Escenario (resumen 6 partes) | (Valor, Riesgo) | Justificación |
|---|---|---|---|---|
| Disponibilidad | Recuperación tras falla de servidor | Fuente de estímulo: hardware del servidor de historias clínicas · Estímulo: falla por crash · Ambiente: horario de atención · Artefacto: servidor de historias clínicas · Respuesta: failover automático a nodo de respaldo · Medida de respuesta: tiempo de conmutación < 30s, 0 pérdida de datos | (H, M) | H de negocio: sin historia clínica no se puede atender; M de riesgo: failover ya probado en staging |
| Seguridad | Confidencialidad de datos de pacientes | Fuente de estímulo: atacante externo no autenticado · Estímulo: intento de acceso a historia clínica sin permisos · Ambiente: sistema expuesto a red pública · Artefacto: API de historias clínicas · Respuesta: bloquear el acceso, registrar el intento, alertar al equipo de seguridad · Medida de respuesta: 100% de intentos no autorizados bloqueados y registrados, alerta emitida en < 1 min | (H, H) | H de negocio: incumplimiento regulatorio (ej. HIPAA/ley de datos de salud) tiene multas y pérdida de licencia; H de riesgo: superficie de ataque grande, aún no auditada completamente |
| Rendimiento | Tiempo de respuesta al consultar historia clínica | Fuente de estímulo: médico usando la app clínica · Estímulo: solicitud de ver historia clínica de un paciente · Ambiente: carga pico (guardia, turno mañana) · Artefacto: servicio de consulta de historias clínicas · Respuesta: el sistema devuelve la historia completa · Medida de respuesta: tiempo de respuesta p95 < 800ms bajo carga pico | (M, M) | M de negocio: demoras cortas son tolerables, pero afectan la atención; M de riesgo: requiere optimizar consultas, no es trivial pero es conocido |
| Modificabilidad | Agregar un nuevo tipo de estudio médico al sistema | Fuente de estímulo: desarrollador del equipo clínico · Estímulo: pedido de soportar un nuevo tipo de estudio (ej. resonancia) · Ambiente: tiempo de diseño, próximo release · Artefacto: módulo de registro de estudios · Respuesta: se agrega el nuevo tipo sin modificar los módulos de historia clínica ni de facturación · Medida de respuesta: cambio confinado a ≤ 2 componentes, ≤ 16 horas-persona | (L, L) | L de negocio: deseable pero no bloquea la operación actual; L de riesgo: el módulo ya está diseñado para nuevos tipos de estudio |

**Candidatas a analizar primero en la evaluación de arquitectura (cuadrante H,H):** la hoja de Seguridad (confidencialidad de datos de pacientes) es la única en (H,H) — se prioriza sobre las demás.
